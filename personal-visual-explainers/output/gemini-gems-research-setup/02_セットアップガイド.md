# Gemini Gems セットアップガイド（調査・学習サポート版）

技術トピックの調査・学習をサポートする Gem のセットアップ手順書。
HTML図解は生成せず、**Markdown形式の高品質な解説**を出力する。

---

## 前提条件

- **Gemini Advanced**（Google AI Pro / Ultra プラン。Gem のファイル添付に必要）
- モデルは **Gemini 3.1 Pro**（現行で選べる最新の Pro 系）。Flash は速度優先用なので使わない
- ウェブ検索の特別な設定は不要（Gemini は標準で自動的に検索する。「デフォルトツール」は「ありません」のままでOK）

> 補足: 消費者向け Gem に「Google検索をON」するトグルはありません。Gemini はクエリに応じて自動でウェブ検索します（[Google AI 公式](https://ai.google.dev/gemini-api/docs/generate-content/google-search)）。ただしモデルが検索を省略・偽装することがあるため、**回答に公式の出典URLが付いているか**で実際に検索したかを確認します。徹底的に調べたいときは、デフォルトツールや入力時に **Deep Research** を選ぶ手もあります。

## セットアップ手順

### Step 1: Gem を作成

1. PC で [gemini.google.com](https://gemini.google.com) にアクセス（Gem の作成・編集はウェブ版のみ）
2. 「Gem マネージャー」→「新しい Gem を作成」
3. Gem 名: **「技術調査アシスタント」**（任意でOK）

### Step 2: 指示文を設定

1. 「指示」欄に [`01_Gem指示文.md`](01_Gem指示文.md) の **`---` 以降のテキスト全体** を貼り付け

### Step 3: ナレッジファイルをアップロード

「Knowledge（ナレッジ）」セクションで「ファイルを追加」から以下3ファイルをアップロード（上限10ファイル）:

| ファイル | 用途 |
|---------|------|
| [`model-answer.md`](model-answer.md) | 品質の型（構成・情報量・深さの見本） |
| [`ascii-art-guide.md`](ascii-art-guide.md) | ASCIIアートのパターンと書き方 |
| [`source-citation.md`](source-citation.md) | インライン出典のルール |

**注意:** `model-answer.html` は添付しない（出力は Markdown のため、HTML模範は混乱の元）。

### Step 4: 保存 & テスト

保存して、以下を入力:

```
OAuth 2.0 の仕組みを教えて
```

## 機能確認（検索・ファイルが実際に効くかのチェック）

「unknown（未確認）」の場合、まずこの2つを実機で確認してください。

### 1. Google検索が効いているか

テスト入力:

```
最新のNode.js LTSのバージョンは？公式の出典URLも付けて。
```

- **OK**: 具体的なバージョン番号＋ `nodejs.org` 等の公式URLが返る（検索が効いている）
- **NG**: 「私の知識では…」と曖昧、またはURLなし → 「ウェブで検索して公式の出典URLを付けて」と促す。それでも改善しなければ Deep Research を試す

### 2. ファイル（ナレッジ）が効いているか

テスト入力:

```
添付の model-answer.md に書かれている「まとめ — 覚えておきたい3つのこと」を3つそのまま挙げて。
```

- **OK**: ファイル内の3項目を正しく引用できる（ナレッジが読めている）
- **NG**: 答えられない／創作する → ファイルが添付・認識されているか再確認

## 動作確認チェックリスト（最終回答の品質）

- [ ] 構成が揃っている（1.とは？ / 2.本質・原理原則 / 3.図解ASCII / 4.解説 / 5.身近な接点 / 6.設定方法※設定が関わる場合）
- [ ] 冒頭に40字以内の「ざっくり一言」がある
- [ ] 「身近な接点」で読者の実体験に結びつく具体例が2〜4個ある
- [ ] 設定が関わる技術では「設定方法・主要な設定値」が手順＋設定値の表＋注意点で示されている
- [ ] 原理原則が3点以上、「なぜ」が説明されている（機能列挙で終わっていない）
- [ ] ASCII図解がコードブロックで出力されている
- [ ] 数値・仕様・制約に公式の出典URLが対応している
- [ ] 末尾に「参照した一次情報」がある
- [ ] Qiita・Zenn・Wikipedia が出典に含まれていない
- [ ] 「初心者向け」等の読者レベルラベルがない
- [ ] 調査ログやチェック表など、過程が出力されていない（最終回答だけ）

## 使い方

```
{トピック}の仕組みを教えて
```

```
{トピック}について調べて
```

### 仕組み理解 → 設定値検証の流れ

まず仕組みを理解し、次に具体的な設定を深掘りする使い方:

```
1通目: {製品}の{機能}の仕組みを教えて
2通目: その{機能}の設定値を詳しく。各設定の意味・推奨値・根拠URL付きで。
```

### 追加テスト用プロンプト

| 入力 | 確認ポイント |
|------|-------------|
| `Kubernetes の Pod とは何か` | 浅い機能説明に逃げていない。原理3点以上 |
| `SAML認証の仕組み` | 公式・RFCが出典。Qiita等なし。シーケンスがASCII |
| `RADIUS認証のフェイルオーバー` | 設定値と動作の対応がASCIIで示されている |

## 品質が低いときの追い打ち

### 検索していない／出典が弱い

```
記憶ではなく、Google検索で公式ドキュメントを確認してから書き直して。数値や仕様には公式の出典URLを付けて。
```

### 二次情報を使っている

```
出典にQiita/Zenn/Wikipedia等が混じっています。一次情報（公式・RFC）のみで確認し直して書き直して。
```

### 原理が浅い／情報量が足りない

```
model-answer.md と同等の深さで書き直して。原理は最低3点、それぞれ「なぜ」を1段落以上。ASCII図解は省略しないで。
```

### 模範の比喩をそのまま流用している

```
レストランの比喩は model-answer.md の例です。このトピックに合った比喩を新しく作って。
```

## トラブルシューティング

| 症状 | 対処 |
|------|------|
| 検索せず記憶で答える／URLが出ない | 「ウェブで検索して公式を確認して」と促す。改善しなければ Deep Research を選んで再実行 |
| 添付ファイルを参照しない | Knowledge にファイルがあるか確認。機能確認テスト2を実行 |
| ASCIIが省略される | 「図解はASCIIをコードブロックで必ず出力して」 |
| 原理が浅い | 「原理を3点、それぞれ"なぜ"を説明して」 |
| 回答が短すぎる | 「model-answer.md と同等の情報量で書き直して」 |
| HTMLが出力される | 「Markdownのみで。HTMLは禁止」 |
| 読者レベルに言及する | 「"初心者向け"等のラベルは付けないで」 |
