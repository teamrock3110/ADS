# 提案者プロフィール（記入例）

このファイルをコピーして `profile.md` を作る。
提案の内容が変わっても書き換えない項目だけを入れる。特定の案件の話は書かない。

Claude で使うときは、`profile.md` の内容をプロジェクトナレッジに貼る。

## 立場

- 所属・役割：（例）情報システム部門。社内IT運用が中心
- 実行力：（例）試作・実装まで自分でできる ／ 企画までで実装は別チームに依頼する

## 提出チャネルと体裁

- （例）Slack の DM に投稿する ／ 1on1 で口頭説明する ／ ドキュメントにまとめる
- 文字数：（例）全体800字以内。コードブロックは字数から除外する
- 改行：（例）文章の自然さを優先する。明らかに長い行だけ、意味の区切りで改行する（目安50字）
- 見出し記号：（例）セクション見出しは ■。下位階層は ■ → ◎ → ・ の順
- markdown 装飾：（例）使わない。貼り付け先で崩れる
- 絵文字：（例）使わない

## 文体

- 語尾：（例）「〜したいです」で終える
- 数字の書き方：（例）計算式を添える（5分 × 4件/日 × 20営業日 ＝ 月6.7時間）
- （例）一文一義

## 使わない言葉

- （例）無駄 / 非効率 / 間違い（過去の運用を否定して聞こえる）

## 承認が必要な行為

能力A（承認者の設計）で「権限が増えるか」を判定するときに参照する。
費用は発生しなくても承認が必要な行為は、決裁ルートを一段上げる材料になる。

- （例）API の利用：費用は発生しないが権限の承認が必要
- （例）社外サービスへのデータ送信：禁止されている

## よく使う数字の出どころ

一発出しで数字を推測しないために、参照先を控えておく。

- （例）対象台数と検知件数：管理コンソールの画面
- （例）申請件数と待ち時間：申請フローの管理台帳
