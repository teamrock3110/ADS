# 相手カード（記入例）

このファイルをコピーして `audiences.md` を作る。
**このファイルは必須ではない。**カードがない相手には、SKILL.md の能力C（5属性）を対話で埋めればよい。
よく提案を出す相手だけカードにしておくと、その相手への質問が省略される。

Claude で使うときは、`audiences.md` の内容をプロジェクトナレッジに貼る。

## カード1枚のテンプレート

```
## （相手の呼び方）

- 決めること：（この人が決裁できる範囲。承認ではなく合意が必要な相手ならそう書く）
- 決裁権の範囲：（金額・影響範囲の上限。超えたら誰に上がるか）
- 責任回避志向：（高い／低い。高いなら責任の所在と可逆性を示す必要がある）
- 技術評価志向：（高い／低い。高いなら技術の筋を短く示す。出典は争点になるときだけ）
- 読む量：（多い／普通／少ない。少ないなら文字数を絞る）
- 関心：（この人がいつも気にすること）
- 逆鱗：（絶対に踏んではいけない点）
- 過去の当事者性：（現行の仕組みを作った／続けてきた側かどうか）
- 効くレバー：（この人に対して実際に効いた通し方）
- 通し方：（誰を先に通すか。単独で完結するならそう書く）
```

## 記入例

```
## 直属のマネージャー

- 決めること：部門内の運用変更。実質のゲートキーパー
- 決裁権の範囲：予算を伴わない範囲
- 責任回避志向：低い
- 技術評価志向：高い。技術的に筋が通っているかを最重視する
- 読む量：普通。口頭でも通る
- 関心：ユーザ影響 / 期限 / 優先度 / コスト / 公式情報ベースの根拠
- 過去の当事者性：現行の運用を作ってきた側
- 効くレバー：技術の筋（何をする／何を変えない／誰が最終判断するか）、可逆性、自分の工数と優先度、ユーザ影響の小ささ。出典は争点になるときだけ
- 通し方：単独で完結する

## 他部署の担当者

- 決めること：協力するかどうか（決裁ではなく合意）
- 決裁権の範囲：自分の業務の範囲だけ
- 責任回避志向：高い
- 技術評価志向：低い
- 読む量：少ない
- 関心：自分の仕事が増えないか
- 効くレバー：相手の手間を先に引き受ける、期限を相手に選ばせる
- 通し方：自部門の承認を取ってから依頼する
```
