# Writing Proposals

「◯◯を変えたい」というざっくりした思いつきから、AIが対話で材料を引き出し、相手に刺さる提案文書を作ってくれるスキルです。

意思決定者に「それで！」と言わせる、結論ファーストの提案文に仕上がります。

**一発出し前提**で設計されています。出力された提案文をそのまま提出でき、手で書き換える必要がないことを目標にしています。そのぶん出力前の対話は長くなります。材料の確認や骨子の合意は、何往復してもかまいません。

## 何ができるか

- 提案に必要な材料を1問ずつ質問してくれる
- 「どうしますか？」ではなく「◯◯がおすすめ、理由はこう」と推奨案つきで聞いてくる
- 過去に書いた文章を渡すと、あなたの文体に寄せてくれる（任意）
- 誰の承認が必要かをAIが設計してくれる（金が動く・全社影響・権限が増える・他部署の業務が変わる場合は決裁が一段上がる）
- 提案の性質を4つ判定し、必要な材料を自動で切り替えてくれる（ツール導入でも運用ルール変更でも同じスキルで通る）
- 相手を属性で捉えるので、初対面の相手でも1〜2問で書き方が決まる
- 根拠の最後を「絵の浮かぶ場面」で締めてくれる（文体はビジネスライティングのまま、材料だけストーリーライティングを1文混ぜる）
- 完成文の前に骨子と仮定を見せてくれるので、ズレが本文に混ざる前に潰せる
- 出力がズレたとき、どこを直せば次回から防げるかを診断してくれる

テンプレートを機械的に埋めるのではなく、**書く前に「上流」（誰に・何を・なぜ）を整える**ことに専念します。

## 使い方

提案したいことを書いて、以下のように依頼するだけです。

```
定例会議を減らす提案を作って
```

```
◯◯を提案したい
```

```
提案書を書いて
```

AIが1問ずつ質問してくるので、答えていけば提案文書ができあがります。最初にわかっている情報はまとめて渡してもOKです。

## こんなときに使う

- 上司やチームに何かを提案したいが、どう書けば通るか分からないとき
- AIに丸投げすると「当たり障りのない薄い文章」しか出てこないとき
- 自分の作ったツールや改善案を、決裁権を持つ人に通したいとき
- 提案の根拠をどう組み立てればいいか迷うとき

## 初回のセットアップ

用意するのは2ファイルだけです。**なくても動きますが、あると毎回聞かれる質問が減ります。**

| ファイル | 中身 |
|---|---|
| `context/profile.md` | 自分の情報（立場・提出先・文字数・文体・使わない言葉） |
| `context/audiences.md` | 相手の情報（決裁権の範囲・関心・読む量・効くレバー） |

同じ場所にある `profile.example.md` と `audiences.example.md` をコピーして書き換えます。この2ファイルは人物評と社内情報を含むため、gitでは追跡されません（`.gitignore` 済み）。

## Claude で使う場合

1. `writing-proposals` フォルダを zip にする（**zipの直下にフォルダが来るようにする**。ファイルを直置きすると読まれません）
2. Claude の Settings > Capabilities > Skills からアップロードする
3. 提案用のプロジェクトを作り、上の2ファイルの中身をプロジェクトナレッジに貼る

`SKILL.md` と `references/` を直したときは再zipと再アップロードが必要です。`context/` の2ファイルはブラウザで貼るだけで直せます。だから普段更新するのは後者だけです。

Claude.ai の制約が2つあります。`description` は200文字までです。またアップロードしたスキルは読み取り専用なので、AIがスキルを書き換えることはできません。

## 出力がズレたときの直し方

文章を直すのではなく、原因を切り分けて修正先にパッチを当て、最初から実行し直します。AIに症状を伝えると、診断して貼り付け用のパッチを出してくれます。

| 症状 | 修正先 |
|---|---|
| 数字や事実が足りない・違う | `profile.md` の「よく使う数字の出どころ」 |
| 相手に刺さっていない・想定質問が外れた | `audiences.md` の相手カード |
| 自分の言い回しでない・長すぎる・体裁が崩れた | `profile.md` の文体と提出チャネル |
| 承認者や通す順番が違った | `audiences.md` の決裁権の範囲 |
| 論理が飛ぶ・代替案がない・結論が弱い・プレースホルダが入った | `SKILL.md` 本体（持ち帰り課題） |

上4つは `context/` の2ファイルを直すだけで済みます。Claude.ai では、その中身を貼ったプロジェクトナレッジを直します。会社のブラウザからでも作業できます。最後の1つだけ `SKILL.md` の修正が必要で、Claude.ai なら zip の作り直しも要ります。

**使うほどコンテキストが育ち、質問とズレが減っていきます。**最初から完璧なコンテキストを用意する必要はありません。粗く始めて、必要になった箇所だけ足していきます。

足すきっかけは2つあります。出力がズレたときは、上の表で診断します。うまくいったときも、コンテキストに無くて対話で聞いた項目をAIが出力後に1行で報告します。気になったときだけ「足して」と伝えれば、貼り付け用のテキストが出てきます（Cursor では AI がファイルを直接書きます）。放置してもかまいません。

## フォルダの中身

```
writing-proposals/
├── README.md                   ← この説明書
├── SKILL.md                    ← スキル本体（AIへの指示書）
├── context/                    ← プロジェクトナレッジに貼る内容
│   ├── profile.md              ← 自分の立場・体裁・文体（gitで追跡しない）
│   ├── profile.example.md      ← その記入例
│   ├── audiences.md            ← 相手カード（gitで追跡しない）
│   └── audiences.example.md    ← その記入例
└── references/
    ├── examples.md             ← 提案文書の模範例
    └── output-quality.md       ← 出力品質チェックリスト
```

## 困ったとき

何が起きても、まずはチャット欄でAIに状況を伝えてください。AIが内容を読み取り、次にやるべきことを教えてくれます。
