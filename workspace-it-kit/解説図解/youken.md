# グリル結果（2026-07-04 確定）

## 決まった事

### 形式・公開先
- HTML 1ページの縦スクロール図解を作成し、**surge.sh** に公開してURL提出
- サブドメイン仮置き: `workspace-it-kit-zukai.surge.sh`
- 制作フローは creating-visual-explainers（HTML生成→surge公開）を利用

### トーン
- シンプルな技術図解。キャラクター寸劇はなし
- 専門用語（API・DB・Jira等）には出てきた場所で一言解説を添える
- 例え話を使う（例: 図書館の本と付箋 = Master と Overlay）
- 新卒1年目の社会人にも伝わる粒度にする

### 保持データの見せ方（2段構成）
1. 画面キャプチャ（`解説図解/アプリ画面.png`）にペイン別データを注釈
2. その下で2層モデル図に落とす
   - **Master（タスクの骨格）**: タイトル・期限・概要・コメント → `tasks.json`
   - **Overlay（自分の作業データ）**: 作業メモ・報告3欄・関連リンク・完了チェック・追加タスク → **Neon DB**
   - 2層はタスクID（例: ITDX-142）で紐付け

### 保存先と理由（3段で語る）
1. **率直な動機**: JSONファイルでも実現できたが、「データベースを使う」という選択肢を自分の経験として持ちたかったのでDB構成にした（↑本文の追記を反映。正直な語り口は共感を呼ぶので冒頭に置く）
2. **設計上の合理性**: 将来のJira連携を見据えた **Master/Overlay分離** — 骨格の取得元を tasks.json → Jira API に差し替えても、Neon上の作業データはタスクIDで紐付いたまま残る
3. **移行の経緯**: 最初はlocalStorage（ブラウザ保存）だったが、端末・ブラウザごとにデータが分断され、履歴削除で消えるリスクもあるためNeonへ移行した

### 工夫したポイント（3点・本文の記載どおり）
1. 会社のタスク管理ツール（Jira）と連携できる設計（未実装・構想である旨を明記）＋手動タスク追加
2. 関連リンクを1クリックで追加して情報を追いやすく（ペイン2）
3. AI生成機能 — 手動入力/AI生成の2択、Claude・Gemini 2つのAPIを切替可能

### 苦戦したポイント（1点）
- **AI生成のフォーマット指定**
  - 3つの会議ごとに貼り付け先のフォーマットが異なる（Googleドキュメント・OneNote等）
  - 会議ごとにコピペで完結できるよう、インデント形式（タブ文字、スペース2つ＋アスタリスク等）の調整が大変だった
  - 実装箇所: `lib/report-prompts.ts`（会議別に出力フォーマット規則を定義）
