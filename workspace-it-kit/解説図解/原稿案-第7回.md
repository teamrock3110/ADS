## 0. ヒーロー（つかみ）

- バッジ: 業務ツール
- タイトル: **タスク別 週次報告ワークスペース**
- リード: 毎週の定例報告を「探して・書いて・整える」から解放するために、コーポレートIT担当が自分の業務のために作ったツールです。

**一言の答え**
> タスクを「選ぶ → 読む → 書く → 確認する」。3つの定例に出す報告を、1画面のまま作り終えるツール。

**コア図（一枚絵サマリー）**
4ペインの横帯を描き、その右に出口として定例3つを置く。

```
 P1 選ぶ  →  P2 読む  →  P3 書く  →  P4 確認する ─┬→ 月：センター定例
 タスク一覧   概要・メモ   進捗・課題   週次報告書   ├→ 火：PJ定例（1案件）
 期限/遅延順  関連リンク   相談3欄      プレビュー   └→ 金：PJ定例（週の状況）
```

**身近な接点ピル**: 週次報告 / 定例会議 / Jira / Slack / コピペ整形

橋渡し: 「ここから、この画面が何を解決しているのかを順に見ていきます。」

## 1. ツールの画面（キャプチャ）

最新UIを撮り直して掲載（dev起動 → 全体1枚 ＋ ペイン拡大）。

キャプチャに添える注釈（ペイン別・4本）:

| ペイン | 見出し | 一言 |
|---|---|---|
| P1 | 選ぶ | 担当タスクを期限・遅延順に並べる。ここが1日の起点 |
| P2 | 読む | タスクの概要・コメント・作業メモ・関連リンクを1枚に集約 |
| P3 | 書く | 報告の材料を3欄（今週の進捗／遅延理由・課題／相談・承認依頼）で入力 |
| P4 | 確認する | 定例ごとの報告書をプレビュー。手動／AI生成を切り替えてコピー |

注記: 画面のデータはすべてモックです（社内の実データは含みません）。

## 2. ツールで解決できる課題

導入文: 週次報告そのものは、机に向かえば終わる作業です。しんどいのは「書く」ことではなく、**書き始める前と、書き終えた後**でした。

### 課題1: 情報が3か所に散らばっている

図（Before）: 中央に自分、周囲に Jira / Slack / Googleドキュメント・シート を置き、往復の点線矢印。
- Jira ＝ チケットの状態とコメント履歴
- Slack ＝ 依頼スレ・関係者とのやりとり
- Googleドキュメント／シート ＝ 設計書・手順書・台帳

「今週このタスクで何が動いたか」を思い出すために、毎回3か所を往復してタブを開き直していた。

図（After）: 1つのワークスペースに集約。タスクごとに関連リンクを登録してあるので、必要な資料は**1クリックで開く**。

### 課題2: 定例ごとに報告の形式が違う

3つの定例で、求められる粒度も記法も違う。

| 定例 | 内容 | 形式 |
|---|---|---|
| 月：センター定例 | チーム業務全体 | ★カテゴリ ／ ○案件 ／ ・詳細 ／ →次アクション（タブ字下げ） |
| 火：PJ定例 | 1案件を深掘り | 見出し＋箇条書きのネスト（Markdown） |
| 金：PJ定例 | 今週の状況報告 | ■○・＋ ☑／□ で完了と予定を分ける（タブ字下げ） |

同じ1週間の出来事を、3回書き直していた。

### 課題3: 貼り付け先で整形し直す

出来上がった文章を Googleドキュメントや OneNote に貼ると、字下げや記号が崩れて手直しが発生する。「書き終えてから、まだ作業が残る」状態だった。

**Before / After（工程図・数値は出さない）**

```
Before   Jiraを見る → Slackを遡る → 資料を探す → 書く → 3定例ぶん書き直す → 貼って整える
After    タスクを選ぶ → 3欄に書く → 定例を選んでコピー
```

## 3. 工夫したポイント（4点）

### 工夫1: 定例別に「出力の型」を分けた
月・火・金の3定例それぞれに、出力フォーマットのルールを別々に定義（`lib/report-prompts.ts`）。ツール側が定例を知っているので、同じ入力から3種類の報告文が出せる。
図: 1つの入力 → 3方向へ分岐するファネル図。

### 工夫2: 手動入力とAI生成の2モード、モデルも切り替え可能
報告本文は自分で書いてもいいし、AIに生成させてもいい。AIは **Claude と Gemini** を切り替えられる（`lib/ai/`）。複数モデルを1つのアプリから扱う練習も兼ねた。
生成結果は下書きとして扱い、**手入力の内容を壊さない**（気に入らなければ破棄できる）。
図: トグルUIの再現（手動｜AI）＋モデル選択のピル。

### 工夫3: 関連リンクを1クリックで
タスクごとに Slack スレ・設計書・台帳などのリンクを登録／編集／削除できる（P2）。課題1の「散在」に対する直接の答え。
図: リンクカードのUI再現（ラベル＋外部リンクアイコン）。

### 工夫4: Jira連携を見据えた2層構造
- **Master（タスクの骨格）** = タイトル・期限・概要・コメント → 現在は `data/tasks.json`
- **Overlay（自分の作業データ）** = 作業メモ・報告3欄・関連リンク・完了状態 → Neon（PostgreSQL）
- 2層はタスクID（例: ITDX-142）で結ぶ

骨格の取得元を tasks.json から Jira API に差し替えても、自分が積み上げた作業データはそのまま残る。手動でのタスク追加にも対応。
図: 2層＋IDで紐付く階層ブロック図（例え: 図書館の本＝Master、貼った付箋＝Overlay）。

## 4. 苦戦したポイント

### AIに「フォーマット」を守らせるのが一番難しかった

文章の中身より、**記号と字下げ**でつまずいた。とくに火曜のPJ定例はMarkdownの2階層の箇条書きで、生成物をそのまま貼ると階層が潰れて読めなくなる。

図: 左右のBefore/After（コードブロック風）

```
Before（崩れる）                          After（そのまま貼れる）

# 6G非対応PC 接続設定配布 週次報告        ### 進行中のアクションアイテム
## 進行中のアクションアイテム              * MDM未登録端末の洗い出し：5/20完了
- MDM未登録端末の洗い出し(5/20完了)          * 対象80台のうち23台が未登録
    - 対象80台のうち23台が未登録           * 接続設定プロファイルの配布：5/22予定

・頼んでいない前置きの見出しがつく         ・「### 進行中のアクションアイテム」から始まる
・記号が「-」に化ける                     ・項目は「* 」、詳細はスペース2つ＋「* 」
・字下げが4スペースになり2階層目が潰れる   ・2階層までに固定
・完了表記が「(5/20完了)」と揺れる         ・「：M/D完了」で統一
```

- 原因: 貼り付け先（Googleドキュメント／OneNote）ごとに効く字下げが違う。火曜はスペース2つ＋アスタリスク、月曜・金曜はタブ文字と、定例ごとにルールが分かれる
- 対応: 定例ごとにプロンプトを分離し、記号・インデント幅・日付表記（M/D）・出力の開始位置まで明文化。「コピーしてそのまま貼れる」を合格ラインにして調整を繰り返した
- 実装箇所: `lib/report-prompts.ts`
