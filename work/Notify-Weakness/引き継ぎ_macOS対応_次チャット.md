## 1. 何を作ったか（30 秒）

既存の「NW機器 脆弱性ウォッチャー」（Google スプレッドシート + Apps Script）に、
**macOS リリース監視モジュール**を追加した。

毎朝 Apple Security Releases から macOS のリリースを取り、
**「早めに当てるか・定期更新まで待てるか」**を固定ルールで判定して Slack へ出す。

- **判定はコード。AI は Apple の修正内容を日本語に要約するだけ**
- 情報源は **Apple Security Releases 1 本**（`support.apple.com/en-us/100100`）
- 緊急の根拠は **Apple の実悪用記載**と **CISA KEV**。どちらも公式から直接取る
- NW とはトリガー・シート・台帳が別。片方が落ちてももう片方は止まらない
- **1 リリース 1 通知。**赤も緑もそのリリースの判定として届く

## 4. 利用者の作法（守ること）

- **次の作業は必ず聞いてから動く。**勝手に機能追加しない
- **結論ファーストで答える。**手順の羅列や過度な言い換えは不要
- **「なぜその値・その設計か」を必ず問われる。**根拠のない断定は指摘される。
  適当に置いた値は「根拠はない」と正直に言う
- **「パッチワークになっていないか」「本質からずれていないか」を繰り返し問われる**
- **知らないことは調べる。推測で答えない**
- **行数や工数を、依存関係を確認せずに言わない**
- **忖度のない FB を求められる。**違うと思ったら根拠を出して反論してよい。
  ただし**利用者の指摘のほうが正しかったことが何度もある。**データで確かめてから答える
- コミット・push は依頼があるまでしない
- チームは git を見られない。**運用に必要なことは GAS の `readme.gs` に書く**

## 5. 踏んだ罠（同じ手を二度やらないため）

**すべて「実行は成功したように見えるのに結果が壊れる」型。ローカルのテストでは出ない。**

| 罠 | 教訓 |
|---|---|
| GDMF が SSL Error | Apple 独自ルート CA。`validateHttpsCertificates:false` も効かない。**再挑戦しない** |
| Developer RSS は 11 か月で 53 件しかない | 旧メジャーの更新を載せない。情報源から外した |
| 台帳が空のまま実行だけ成功 | 書く前にシートの行数を確認していなかった |
| 81 版なのに 163 行 | 書いた行より下の古い行を消していなかった |
| 実悪用を調べていないのに「なし」と表示 | **やっていないことを、やった結果の形で記録していた** |
| 初期取込に PENDING と表示 | 同上。「未評価＝調べていない」「未確認＝調べたが分からない」を分ける |
| 初期取込を Phase 2 ごと素通り | **通知を抑えることと、調べないことは別** |
| 緊急と判定した行を握り潰す | 状態を増やして通知を制御すると事故る。1 リリース 1 通知に畳んだ |

**共通する根は「やっていないことを、やった結果として記録する」。**
台帳の値を見たら「これは調べた結果か？」を常に疑うこと。

## 6. 検証のやり方

scratchpad に node のハーネスを置き、GAS の API をスタブして本体をそのまま読み込む
（セッションが変われば作り直す）。

- 実データは Apple 公式ページと CISA KEV を curl で取って使う。**作り話のデータで判定を確かめない**
- **判定ロジックに触るときは、変更前の挙動を全パターン記録してから作業する。**
  前回は 75,600 パターンを記録し、変更後に差分ゼロを示した
- **node で 2 ファイルを連結しても GAS のファイル分離は再現できない。**
  分離が絡む変更は実機の `macosSelfTest()` で確かめる
