## 2. このツールは何をするか（30 秒）

毎朝 Apple Security Releases から macOS のリリースを取り、
**「早めに当てるか・定期更新まで待てるか」**を固定ルールで判定して Slack へ 1 通出す。

- **判定はコード。AI は Apple の修正内容を日本語に要約するだけ。**
- 情報源は **Apple Security Releases 1 本**（`support.apple.com/en-us/100100`）
- CISA KEV と Apple の実悪用記載が緊急判定の根拠。どちらも公式から直接取る
- NW とはトリガー・シート・台帳が別。片方が落ちてももう片方は止まらない

### ファイル

| ファイル | 役割 |
|---|---|
| `macos_release_monitor.gs` | macOS モジュール本体（新規） |
| `fortinet_psirt_watcher_v7.gs` | 既存 NW 本体。**接続点 4 か所だけ変更**（KEV 共通化 / responseSchema / AI 消費計数 / 実行履歴の備考） |
| `fortinet_psirt_watcher_v7_readme.gs` | GAS 側の運用手順。§6 が macOS |

## 3. 利用者の作法（守ること）

- **次の作業は必ず聞いてから動く。**勝手に機能追加しない
- **結論ファーストで答える。**手順の羅列や過度な言い換えは不要
- **「なぜその値・その設計か」を必ず問われる。**根拠のない断定は指摘される。
  適当に置いた値は「根拠はない」と正直に言う
- **「パッチワークになっていないか」を繰り返し問われる。**当てはまらないなら正直にそう答える
- **知らないことは調べる。推測で答えない**
- **行数や工数の見積もりを、依存関係を確認せずに言わない**
- **忖度のない FB を求められる。**利用者の案が違うと思ったら根拠を出して反論する。
  ただし利用者の指摘のほうが正しいことが何度もあった。データで確かめてから答える
- コミット・push は依頼があるまでしない

## 4. 踏んだ罠（同じ手を二度やらないため）

**すべて「実行は成功したように見えるのに結果が壊れる」型。ローカルのテストでは出なかった。**

| 罠 | 教訓 |
|---|---|
| GDMF (`gdmf.apple.com`) が SSL Error | Apple 独自ルート CA。`validateHttpsCertificates:false` も効かない。**再挑戦しない** |
| 台帳が空のまま実行だけ成功 | 書く前にシートの行数を確認していなかった |
| 81 版なのに 163 行 | 書いた行より下の古い行を消していなかった |
| 実悪用を調べていないのに「なし」と表示 | **やっていないことを、やった結果の形で記録していた** |
| 初期取込に PENDING と表示 | 同上。「未評価＝調べていない」「未確認＝調べたが分からない」を分ける |
| 初期取込を Phase 2 ごと素通り | **通知を抑えることと、調べないことは別** |
| 緊急と判定した行を握り潰す | 新しい版があることは、古い版の緊急判定を捨てる理由にならない |

**共通する根は「やっていないことを、やった結果として記録する」。**
台帳の値を見たら「これは調べた結果か？」を常に疑うこと。

## 5. 検証のやり方

`/private/tmp/.../scratchpad` に node のハーネスがある（セッションが変われば作り直す）。
GAS の API をスタブして本体をそのまま読み込み、実データで回している。

- 実データは Apple 公式ページと CISA KEV を curl で取って使う。**作り話のデータで判定を確かめない**
- **判定ロジックに触るときは、変更前の挙動を全パターン記録してから作業する。**
  前回は 75,600 パターンを記録し、変更後に差分ゼロを示した
- **node で 2 ファイルを連結しても GAS のファイル分離は再現できない。**
  分離が絡む変更は実機の `macosSelfTest()` で確かめる
