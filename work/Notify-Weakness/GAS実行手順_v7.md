## 2. スクリプト プロパティ（未設定なら）

**プロジェクトの設定 → スクリプト プロパティ**

| キー | 用途 |
|---|---|
| `GEMINI_API_KEY` | 影響機能・確認方法・ユーザ影響（Fortinet 判定用の機能分類も含む） |
| `SLACK_WEBHOOK_URL` | Slack 通知（任意） |

**Cisco openVuln API は GAS では使わない。**  
Key/Secret 自体は有効（手元 `curl` で確認済み）だが、`UrlFetchApp` が `id.cisco.com` で Access Denied になる。  
`CISCO_API_CLIENT_*` は不要です。Cisco の更新先版番号は次のいずれかになります。

- CSAF の Workarounds から取れたコマンド（あれば）
- 「更新先はアドバイザリで確認」（セルがアドバイザリへのリンク）

**失敗通知**: `main()` が例外で落ちると、実行アカウント宛にメールが飛びます
（件名 `[脆弱性ウォッチャー] main() 失敗`）。GAS のメール送信権限の承認が初回に必要です。

## 3. 移行（列構成が変わった場合）

```
① migrateLedgerHeaders()   ← 台帳13列 / 処理済み7列に更新
② migrateAssetHeaders()    ← 初回のみ
③ clearRunData()           ← メニュー「脆弱性ウォッチャー → データ削除」
④ main()
```

`clearRunData()` は **資産シートは触りません**。
今回は自社影響の語彙（`対応推奨` → `あり（対応検討）` 等）が変わっているため、
③ を必ず実行して旧データを残さないでください。

### 期待される結果

**台帳（13列・左6列固定）**

`自社影響 | 製品 | CVE | 脆弱性名 | CVSS | 最終更新日 | 公式推奨対応 | KEV | 影響機能 | 判定根拠 | 確認方法 | ユーザ影響 | アドバイザリ`

自社影響は Fortinet / Cisco 共通で **あり（対応検討）/ あり（影響調査）/ なし** の3値。
判定根拠と基準は [社内ルール案_OS更新基準.md](社内ルール案_OS更新基準.md) を参照。

| 判定 | 出やすい理由 | 次の行動 |
|---|---|---|
| あり（対応検討） | 常時有効な機能に、外部から無認証で掌握・業務停止に至る欠陥 | 対応時期を検討する |
| あり（影響調査） | 影響機能が設定次第（管理GUI / VPN / UTM など）／版が不明 | 確認方法を実機で実行して振り分ける |
| なし | `PR:H` `PR:L` `AV:L` `AV:P` `AV:A` `UI:R` のいずれか／SSL-VPN 無効／軽微 | 記録のみ |

**脆弱性名**: CSAF / RSS の文書タイトル（最大60字）。パッと見で何の脆弱性か分かるようにする  
**判定根拠**: 2行。1行目 `OS=対象 | KEV=なし`、2行目 `◯◯のため「あり（影響調査）」`  
**確認方法**: 3行（何を見る／何を打つ／どう判断する）。ラベルは表示時に除去  
**ユーザ影響**: 最悪ケース50字以内  
**公式推奨対応**: 英語を出さない。Cisco は回避策コマンドがあればそれ、無ければ「回避策なし。更新先はアドバイザリで確認」（テキスト。リンクはアドバイザリ列）  
**確認方法**: 版該否は済み。設定次第なら設定確認、常時有効なら次アクション（定期更新枠など）  
**ユーザ影響**: CVSS の C/I/A に合わせる（DoS なのに掌握、は出さない）  
**Slack（日次1通）**: 新着がなければ送らない。あるときだけ1通。  
1行目が本体: `新しい脆弱性が発表されました🔍`。2行目: `FortiGate:1件 Cisco:2件`。フッターは `Security NEXTで確認  /  判定台帳を確認`（URLは出さない）。  
各件: `CVE  /  CVSS 5 [中]  /  08/12更新` → 機器 → 内容（AIの日本語要約。無ければタイトルの日本語訳） → 影響 → 推奨対応。  
**台帳に載らない行**: 非保有製品と版が影響範囲外の行（処理済みシートには残る）

### Slack 通知の目的

1. **気づく** — 自社該当の脆弱性公開に気づく  
2. **簡潔にわかる** — CVE・版・機能・被害を2秒で掴む  
3. **公式で決める** — アドバイザリIDリンクから一次情報で対応を決める  
4. **必要なら詳細** — 台帳リンクは任意

通知は最終決定の場ではない。決定は公式アドバイザリ側で行う。  
表示確認（Webhookに送らない）: `testSlackBlocks()`

## 6. うまくいかないとき

| 症状 | 対処 |
|---|---|
| 台帳の列がずれる | `migrateLedgerHeaders()` → `clearRunData()` → `main()` |
| 旧語彙（対応推奨など）が残る | `clearRunData()` を実行していない。実行して `main()` |
| 影響機能が空 | `GEMINI_API_KEY` 確認。未設定時は機能推定＋確認手順テーブルのフォールバック |
| `AI 生成: gemini / 成功 0` | `gemini-3.7-flash` 無料枠（1日20回程度）切れ。現行コードは `gemini-3.6-flash` → `2.5` → `2.0` へ退避。貼り替えて再実行。リセットは太平洋時間の0時 |
| 確認方法が「アドバイザリを確認」だけ | コード側で機能別手順に差し替える想定。再実行後も残るなら報告 |
| 「あり（影響調査）」ばかり | 影響機能が `config` なら正しい挙動。確認方法を実行して振り分ける |
| Cisco の公式推奨対応が「参照」だけ | 想定どおり（GAS では openVuln 不可）。回避策コマンドが CSAF にあればそちらが出る |
| `cisco-sa-notice-*` が台帳に出る | 事前告知であり脆弱性ではない。現行コードでは台帳に出さない。出たらコード貼り替え漏れ |
| Cisco が台帳に出ない | `main()` が空台帳なら一度再取得する。まだなら `reprocessCisco()`。台帳だけ消しても処理済みが残ると再取得しない |
| データ削除で「固定されていない行をすべて削除することはできません」 | 見出し固定のまま全行 delete していた。現行コードは中身を消す。貼り替えてメニューから再実行 |
| KEV 照合失敗 | ログの `KEV 照合失敗` → ネットワーク確認 |

## 7. 発表デモ用の最短確認

1. `判定根拠` が2行になっている（1行目に `OS=` と `KEV=`、2行目に理由と結論）
2. 確認方法にラベルが無く、コマンドがそのまま読める
3. 「なし」の行の2行目が、待てる理由（例: `悪用に管理者権限が必要なため`）になっている
4. Cisco 行 → 公式推奨対応がテキストのみ（リンクなし）。確認方法に show version が無い
5. `countByMonthVendor()` → 月別・ベンダー別の公表件数
