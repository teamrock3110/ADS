# 発表用デモ手順：FG-IR-26-154

**目的**: 「読む」工程の Before/After と、台帳・Slack の出力を6分発表で見せる。

---

## なぜこの例を使うか

| 観点 | 内容 |
|---|---|
| アドバイザリ | FG-IR-26-154「Buffer overread in authd and wad daemon」 |
| 手作業の問題 | 1本にCVEが2つ、製品がFortiOSとFortiProxy。v5は1行に潰していた |
| ツールの改善 | CSAFの `vulnerabilities[]` をそのまま3行に展開 |
| 検証済み | `testCsaf()` の期待値として実装に組み込み済み |

## Before（手作業・v5）

### 手作業でやっていたこと

1. マネージャーから記事URLが届く
2. 記事を読み、CVE-2025-43892 と CVE-2026-59840 を拾う
3. Fortinet PSIRTサイトを探し、アドバイザリ本文を開く
4. 影響バージョン表を読み、FortiOS と FortiProxy の範囲をメモ
5. 自社の FortiOS 7.4.x が範囲内か手で比較
6. 結果をメモ帳に書き、月次報告用に転記

### v5の問題（1行に潰す）

```
CVE: CVE-2025-43892, CVE-2026-59840
製品: FortiOS, FortiProxy（混在）
影響バージョン: FortiOS >=7.4.0|<=7.4.8 / FortiProxy >=7.4.0|<=7.4.13（混在）
```

→ **どのCVSSがどのCVEのものか分からない**（面倒 #5）


## 発表前チェックリスト

### データ準備

- [ ] スプレッドシートに「台帳」「資産」「処理済み」シートがある
- [ ] `main()` を実行済みで、台帳にデータがある
- [ ] 台帳に「あり」「なし」「要確認」が各1件以上ある
- [ ] FG-IR-26-154 の行が台帳にある（なければ `testCsaf()` で存在確認）

### GASテスト（コード変更時は毎回）

```
1. testVersion()   → 17/17
2. testCsaf()      → 3行
3. testJudge()     → 判定根拠にバージョン範囲が入る
4. testAi()        → 影響機能名に製品名が入らない
```

### 発表当日

- [ ] 台帳シートをブラウザで開いておく（左5列固定表示を確認）
- [ ] Slack通知のスクショを用意（ライブデモが不安な場合）
- [ ] 資産シートの実データをマスク（バージョン・台数）
- [ ] スプレッドシートURLを聴衆に見せる場合は閲覧権限を確認

### ライブデモ vs スクショ

| 方式 | メリット | リスク |
|---|---|---|
| ライブデモ | 説得力が高い | ネットワーク・APIキー・GAS実行時間 |
| スクショ | 安定 | 臨場感が下がる |

**推奨**: 台帳はライブ、Slackは事前スクショ（`notifySlack_` は新着がないとスキップされるため）
